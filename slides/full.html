2.2 · Introduction

What is Linux Mint?

What it is

  • A desktop Linux distribution based on Ubuntu LTS: Mint 22.x uses Ubuntu 24.04
  • Its own desktop, Cinnamon, plus MATE and Xfce editions
  • Its own tools: Update Manager, Timeshift, Backup Tool, Login Window
  • Version 22.3 “Zena” came out in January 2026. It is a long term support release, supported until April 2029

Scope of this guide

  • Linux Mint 22.x, Cinnamon edition
  • LightDM login screen, X11 session
  • systemd as the first process
  • Other editions and versions differ in the details
  • For readers who already use the terminal and know basic Unix concepts

Release facts come from the Linux Mint 22.3 release notes. Scope checked on a Mint 22.3 machine.

5.5 · Block 2 · Login process

The order of the login files

Read in this order at graphical login

  1. /etc/profile
  2. ~/.profile
  3. /etc/xprofile
  4. ~/.xprofile
  5. /etc/X11/Xsession.d/* (among them: ~/.xsessionrc, the GPG and SSH agents)
  6. cinnamon-session-cinnamon

Three rules

  • Changes apply at the next login. A new terminal is not enough
  • Never print output or run slow commands in these files
  • A syntax error in ~/.profile can break the login. Keep a text console (Ctrl+Alt+F3) as a way back

Order read from /usr/sbin/lightdm-session on Mint 22.3. Files that don’t exist are skipped.

6.2 · Block 3 · User access

Terminal and shell: two kinds of shell

Terminal window in Cinnamon

  • A non-login, interactive shell
  • Reads /etc/bash.bashrc and ~/.bashrc only
  • Inherits the environment that the session set up at login

Text console (Ctrl+Alt+F3) or SSH

  • A login shell: getty or sshd, then login and PAM
  • Bash reads /etc/profile, then the first one it finds of ~/.bash_profile, ~/.bash_login, ~/.profile
  • Mint ships ~/.profile, which sources ~/.bashrc

Rule of thumb: variables and PATH go in ~/.profile. Aliases, prompt and functions go in ~/.bashrc.

6.5 · Block 3 · User access

cron: schedule a command

minute

hour

day of month

month

day of week

command

30 2 * * * /home/me/bin/backup.sh >> /home/me/cron.log 2>&1

Rules that save you time

  • cron starts with a minimal environment: a short PATH and no desktop session. Use absolute paths
  • Redirect the output to a log file, or you will never see the error
  • The script needs a shebang line and chmod +x
  • Run it by hand first. Then check the syntax with crontab -n <file>

Alternatives

  • A systemd user timer: logs in the journal, and Persistent=true catches up after the machine was off
  • anacron runs the daily, weekly and monthly folders in /etc/cron.* on machines that are not always on
  • Graphical commands such as notify-send need extra setup under cron

7.2 · Block 4 · Services and daemons

Enabling a service

A service starts at boot because of a symlink in a .wants directory. “systemctl enable” creates the link and “disable” removes it. The unit’s [Install] section says where it goes: WantedBy=multi-user.target.

/etc/systemd/system/multi-user.target.wants/cron.service

symlink to

/usr/lib/systemd/system/cron.service

Enabling does not start the service now. Use “start”, or “enable --now” to do both.

Look:

systemctl is-enabled cron

systemctl list-unit-files --state=enabled

7.3 · Block 4 · Services and daemons

The target chain

graphical.target

starts LightDM, the login screen

multi-user.target

cron, NetworkManager and the other services

basic.target

sockets, timers and paths

How to read it

  • Targets are named goals that group units
  • Top to bottom: each target pulls in the one below it
  • Start order is the reverse: bottom first, graphical.target last
  • Units in the same step start in parallel. Only After= and Before= set an order between them

7.6 · Block 4 · Services and daemons

Not systemd: desktop autostart

A systemd unit

  • A background daemon with no window
  • Starts at boot or at login, without a desktop
  • Logs go to the journal
  • Lives in /etc/systemd/system/ or ~/.config/systemd/user/

A desktop autostart entry

  • A program with a window or a tray icon: network applet, update manager, Bluetooth
  • Started by cinnamon-session, not by systemd
  • Exists only during your graphical session
  • Lives in /etc/xdg/autostart/ or ~/.config/autostart/

Firewall: what reaches your ports

A firewall decides which packets may reach your ports. On Mint the front end is ufw, which writes rules for nftables in the kernel. The usual home policy: deny incoming, allow outgoing.

Internet

Network card

Wi-Fi or cable

Firewall

Open port

a listening socket

Program

a service

ALLOWED

A reply to a connection you started. The firewall is stateful, so it remembers your outgoing connections.

DROPPED

A new connection from outside to a port that has no allow rule.

A firewall is a second line of defense. It does not replace turning off services you don’t need.

8.7 · Block 5 · Network and firewall

Docker: safer habits

Safer habits

  • Publish to localhost only: -p 127.0.0.1:8080:80
  • Publish only the ports you need
  • Membership of the docker group equals root on that machine
  • Don’t mount /var/run/docker.sock into containers you don’t trust

Where it matters

  • Behind a home router the risk is smaller: the router blocks incoming connections
  • On public Wi-Fi, a container published on all addresses can be reached by everyone on that network
  • Check the ports: lines in your docker-compose.yml files

Look:

sudo docker ps

sudo docker network ls

ss -tulpn

getent group docker

8.8 · Block 5 · Network and firewall

Public Wi-Fi checklist (laptop)

On a public network the router is not yours, and strangers share the same local network.

  • Firewall active with deny incoming, and no Docker container published on all addresses
  • Sharing and discovery services off if unused: file sharing, avahi, printing (check with ss)
  • Don’t auto-connect to open networks. Prefer WPA2 or WPA3, or your phone’s hotspot
  • Use a VPN for anything sensitive
  • HTTPS only. Treat a certificate warning as a stop sign
  • Lock the screen when you step away. Turn Bluetooth off if unused
  • Install pending updates before you travel

Look:

nmcli -f NAME,AUTOCONNECT connection show

Public Wi-Fi: about VPNs

What a VPN does

  • It encrypts the traffic between your laptop and the VPN server, so people on the same Wi-Fi can’t read it
  • It does not make you anonymous. You move your trust from the Wi-Fi to the VPN provider
  • Mint’s network settings include a VPN section. The OpenVPN plugin is installed, and NetworkManager also documents WireGuard (not tested here)
  • You can also run a VPN to your own home router or server

Two providers that publish independent audits

  • Mullvad
  • Proton VPN
  • A starting point, not an endorsement. No affiliation. The services were not tested here
  • Both offer official Linux apps for Ubuntu, Debian and Fedora. Proton has a Mint guide. Mullvad does not list Mint as supported

SSH as a client

When you connect out to other machines, your private key is the secret to protect. Use an ed25519 key with a passphrase. Give servers only the public key. A “host key changed” warning is a reason to stop, not something to ignore.

Private key. Never share it or copy it around

Public key. Safe to share

SSH: a config example, and the agent

~/.ssh/config (example values)

Host home-server
  HostName 192.168.1.20
  User me
  IdentityFile ~/.ssh/id_ed25519
  ForwardAgent no
 
Host remote-box
  HostName remote.example.org
  ProxyJump home-server

The agent, and hopping through a host

  • ssh-agent keeps the unlocked key in memory, so you type the passphrase once
  • Agent forwarding (-A, ForwardAgent yes) is risky: root on the remote machine can use your agent while you are connected
  • Prefer ProxyJump (-J) to reach a machine through another one

ssh parses this example correctly (checked with ssh -G). “ssh-add -l” reports an error when no key is loaded: that is normal.

9.6 · Block 6 · Hardening, alarms and audit

Example: a desktop alarm for failed logins

~/.local/bin/auth-alert.sh

#!/bin/bash
n=$(journalctl --since "-15 min" --no-pager -q | grep -ci "authentication failure")
if [ "$n" -gt 0 ]; then
  notify-send -u critical "Security alert" "$n failed authentication attempts in 15 minutes"
fi

auth-alert.service

[Service]
Type=oneshot
ExecStart=%h/.local/bin/auth-alert.sh

auth-alert.timer

[Timer]
OnBootSec=5min
OnUnitActiveSec=15min
[Install]  WantedBy=timers.target

Tested: run by its timer as a user service, the notification was sent (with a wider time window, to find old entries). Not tested: a real failed login inside the 15-minute window. Your user must be able to read the journal (group adm or systemd-journal).

The weekly ten-minute checkup

One pass through the look commands of blocks 5 and 6.

  • Update Manager: install pending updates
  • ss -tulpn: any listener you can’t explain?
  • sudo ufw status verbose: still active, still deny incoming?
  • sudo docker ps: any container published on 0.0.0.0?
  • last and sudo lastb: any login you don’t recognize?
  • journalctl -p err -b: new errors since last week?
  • Timeshift: is the latest snapshot recent? And the backup of your home folder?
  • ls -l ~/.ssh: permissions still 700 and 600?
